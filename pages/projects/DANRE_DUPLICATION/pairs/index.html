Each pair gets a folder pairs/<geneA>_<geneB>/ containing:

  • <geneA>_<geneB>.md: the comparison, following the template below.
  • annotation-comparison.md: generated by
    uv run python projects/DANRE_DUPLICATION/scripts/compare_pair.py <geneA> <geneB>.
    It gives protein identity and a side-by-side table of GO annotations. Do not
    edit it by hand; regenerate it after the reviews change.

The two gene reviews themselves live as usual in genes/DANRE/<gene>/.

## 1. Evidence the pair comes from the TGD
PANTHER call and evidence (row in panther_tgd_pairs.tsv: branch, gar/medaka
co-orthologs); synteny or phylogenetic papers; state what is and is not established.

## 2. Protein-level comparison
Identity (from annotation-comparison.md); domain architecture; conservation of
key functional residues/motifs; any biochemical comparison (e.g. activity assays,
cross-rescue). Does each copy retain the ancestral molecular function?

## 3. Expression
Published expression domains of each copy, and of the ancestral (pre-TGD,
e.g. gar) or tetrapod single-copy gene where known. Shared vs copy-specific domains.

## 4. Experimental evidence of function
Per copy: mutants (note the allele type: PTC/NMD vs RNA-less), morphants,
double mutants, rescue and cross-rescue, compensation by the paralog.

## 5. Fate classification
One of: PARTITION (subfunctionalization) / INNOVATION (neofunctionalization) /
BACKUP (redundancy) / DOSAGE / MIXED / UNRESOLVED. Give the level of the claim
(expression vs protein), the evidence for it, confidence, and what would change it.

## 6. GO annotation consistency across the pair
Summarize annotation-comparison.md: asymmetries that are biologically justified
(expression partition, protein divergence) vs artefacts of which copy was
studied; annotations that should be copy-specific; annotations missing from one
copy; how IBA/ISO propagation treats the pair.
