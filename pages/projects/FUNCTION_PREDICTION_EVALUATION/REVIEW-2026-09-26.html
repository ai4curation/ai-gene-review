This page reviews the projects listed in the function-prediction index:
ProtNLM2, BioReason-Pro / GO-GPT,
DeepECTransformer / E. coli,
Affinage and TreeGrafter. It also covers the index
page itself and the shared *-predictions-review.yaml / prediction-browser infrastructure.

The review was AI-generated (Claude Code). Parallel reviewer agents recomputed the headline numbers
from each project's sidecars and per-gene YAMLs, checked relative links, ran schema validation, and
spot-checked individual calls against the gene reviews. The review changed no project content.
Findings are listed with file:line so they can be acted on.

Overall verdict

The infrastructure is in good shape:

  • All 169 prediction-review YAMLs validate.
  • All supported_by quotes checked are verbatim.
  • The prediction browser data.js matches a fresh regeneration.
  • The headline counts on every page reproduce from their own sidecars.

The weaknesses are methodological:

  • The reference standard is not independent. In every project the reference is an AIGR review
    produced by the same agent family, sometimes with the evaluated tool's output already folded in.
  • Novelty is judged against current GOA rather than a training-cutoff snapshot.
  • Several "frozen" results have drifted from the reviews they summarize.

None of the pages currently overstate numbers relative to their data. Several overstate what the
numbers mean.

Cross-cutting issues

  1. Circular or non-independent ground truth (all projects).
  2. BioReason's references, first rater and second rater are all LLM-agent products. The second
    rater's model is not named.
  3. Affinage FA-cohort reviews were built with Affinage input, then used to grade Affinage recall.
  4. The TreeGrafter OpenScientist/Falcon exemplar verdicts were cited back into the source reviews.

Each page should state the independence status of its reference explicitly. Ideally, a small
human-rated subset should anchor the LLM ratings.
2. COR/CNN measure GOA sparsity, not model novelty.
- ProtNLM COR is defined against the target's cached GOA. As a result, horse is 37% COR while
pombe, Neurospora and fly are about 0%. Roughly 16 of 53 COR calls are generic terms entailed
by an existing MF or domain.
- BioReason re-labelled 61 calls to CNN in a current-snapshot audit, 25 of them from COR.

Novelty should be judged against a GOA release at the model's training cutoff, or COR should be
renamed "not in target GOA" and reported per cohort.
3. Failure-mode taxonomies are anecdotal.
- BioReason: 62/147 discordant ARGO95 terms have no error_type, and LOCALIZATION_DEFAULT is
tagged only 4 times, yet the page calls it "systematic".
- Affinage: some "wrong branch" examples contradict our own core_functions.

Report mode counts with denominators.
4. Snapshot drift.
- TreeGrafter: re-running the analysis on HEAD changes 63 actions. 48 of the 306 down-grades are
no longer down-graded, which invalidates two hotspot families.
- ProtNLM: the OpenScientist adjudication report disagrees with about 20 current YAML calls.
- Affinage: recall re-runs give 137 genes at 47%, not 91 at 52%.

Each results section should name the commit it was computed at and a command that reproduces it.
5. Two public views of the same predictions disagree (DeepECTF).
deepectf-eval.html is rendered from the blinded recapitulation copies. That experiment matched
the production calls on only 4/7 genes. The prediction browser shows the production calls.
Neither page says which is which.
6. Generated evaluation tables are not built in CI. render-bioreason-eval
(project.justfile:1532) is not part of build-pages, so sft-eval, gogpt-eval and
deepectf-eval.html refresh only by hand.

Affinage (page)
