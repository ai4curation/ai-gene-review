# ARO ↔ GO mappings & the UniProt→ARO→GO pipeline

Part of the [Antimicrobial Resistance project](../ANTIMICROBIAL_RESISTANCE.md).

## Files

| File | What it is |
|------|------------|
| `aro2go.sssom.yaml` | Curated **ARO → GO** mapping set in [SSSOM](https://mapping-commons.github.io/sssom/) format (source of truth). CURIE+label tuples throughout; validates with `linkml-validate`. |
| `aro_family_triage.yaml` | CARD AMR gene families deliberately **not** mapped, each with a reason (LinkML class `AROFamilyTriage`). |
| `aro_release.yaml` | The CARD/ARO release the mapping was last checked against (CARD 4.0.2, ARO 2026-08-11). |
| `aro_release.py` | Fetches a CARD release, implements propagation (`is_a` and `participates_in`), and checks label drift and family coverage (`just fetch-aro`, `just check-aro-release`, `just aro-family-coverage`). |
| `oak_config.yaml` | OAK config for `just validate-mappings`: ARO from the fetched release, not OLS (OLS lags CARD releases). |
| `FAMILY_COVERAGE.md` | **Generated** status of every CARD AMR gene family: mapped, covered by an ancestor, GO gap, or triaged. |
| `GO_TERM_REQUESTS.md`, `go_term_requests/` | Draft GO new-term requests for the recorded gaps (not filed). |
| `MAPPING_HOME_OPTIONS.md` | Options note: where the mapping should live, release sync, and how annotations would reach GO. |
| `aro2go.terms.yaml` | **Generated** nested term-tuple form of the mapping, validated by `linkml-term-validator` (do not edit by hand). |
| `sssom_to_terms.py` | Converter: reshapes the flat SSSOM rows into the nested `{id,label}` form the term-validator checks. |
| `uniprot2aro2go.py` | Pipeline that chains **UniProt → ARO → GO** by applying the SSSOM mapping. |
| `aro2go.html` | **Curator-facing HTML** view of the mappings + gaps (CARD/AmiGO links). Generated by `render_sssom_html.py` (`just render-mappings`). |
| `ANNOTATION_GAIN.md` | Report of candidate GO annotations UniProt would gain. Generated by `annotation_gain_report.py` (`just annotation-gain`). |
| `data/uniprot_card_xrefs.tsv` | Snapshot of UniProtKB entries with a CARD cross-reference (ARO id + existing GO), from the UniProt REST API. |
| `data/candidate_new_annotations.tsv` | One row per (entry, candidate new GO term) produced by the gain report. |
| `data/mapping_row_stats.tsv` | Per mapping row: entries matched, new, already annotated, subsumed (read by the HTML view). |
| `examples/rgi_example_mphA.txt` | Tiny example of CARD RGI tab-delimited output, used to demonstrate the sequence-based route. |
| `examples/rgi_example_betalactamases.txt` | RGI example (CTX-M-15/KPC-2/NDM-1) demonstrating propagation from the beta-lactamase family node (`narrower`) and the antibiotic-inactivation mechanism (`participates_in`). |

## Curator view & annotation-gain report

- **`just render-mappings`** → `aro2go.html`: every mapping row with the ARO relation it propagates
  along, its confidence, who reviewed it, how many CARD-cross-referenced UniProt entries it reaches,
  how many would gain a new annotation, and in words why a row yields zero. Gap rows link to the drafted
  GO term requests.
- **`just annotation-gain`** → `ANNOTATION_GAIN.md` + `data/candidate_new_annotations.tsv` +
  `data/mapping_row_stats.tsv`: applies the mappings to all **4,182** UniProtKB entries that carry a
  CARD cross-reference and reports the GO terms they would gain that are **not already annotated**
  (subsumption-aware: a candidate is suppressed when the entry already has a more specific term).

| | before (2026-06, is_a only, 32 rows) | after (2026-11-27, is_a + participates_in, 66 rows) |
|---|---:|---:|
| entries matched by ≥1 mapping | 3,609 | 4,176 |
| entries gaining ≥1 new candidate | 630 | 1,158 |
| candidate new annotations | 630 | 1,784 |
| entries reached by the mechanism rows | 0 | 4,176 |
| CARD AMR gene families with a GO term (directly or via an ancestor) | 314 | 342 |
| families recorded as GO gaps | 8 | 23 |
| families not mapped and without a recorded reason | 273 | 0 |

The mechanism rows alone contribute 1,112 new `GO:0046677` response to antibiotic candidates: 3,062
of the entries they reach already carry it. (An earlier version of this page said every CARD entry
already had the term; that was an artefact of the mechanism rows reaching nothing.) Family counts
for "before" are the old mapping evaluated against the CARD 4.0.2 release.

## Validation: `just validate-mappings`

Three layers, all run by the recipe (and by `tests/test_aro2go_mapping.py`):

1. **Structural** — `linkml-validate` against the SSSOM LinkML schema (required slots, shape).
2. **Ontology terms** — `linkml-term-validator` checks every **ARO** and **GO** CURIE in the mapping
   both *resolves* (ARO via `sqlite:obo:aro`, GO via `sqlite:obo:go`) and that the supplied **label
   matches the ontology label** — the "curie+label tuple" guarantee. This uses the sidecar schema
   `src/ai_gene_review/schema/aro_go_mapping.yaml`, whose `subject`/`object` are `{id,label}` tuples
   with `bindings` to dynamic enums (`AROTermEnum` reachable from `ARO:1000001`; `GOTermEnum` from the
   three GO roots). Prefix→adapter resolution is configured in `oak_config.yaml` in this folder,
   which reads ARO from the fetched CARD release (`.cache/aro/aro.obo`); the recipe passes
   `--no-cache` so the committed `cache/aro/terms.csv`, which predates CARD 4.0.2, cannot answer.
3. **ARO release** — `aro_release.py check` (also `just check-aro-release`): every ARO id in the
   mapping and the triage is live in the pinned release with the same label, the mapping set's
   `subject_source_version` matches `aro_release.yaml`, and every CARD AMR gene family is mapped,
   covered by a mapped ancestor, a recorded gap, or triaged (and no triaged family has become mapped).

A label typo or a wrong id fails the build, e.g.:
`Label mismatch for 'GO:0050073': expected 'macrolide 2'-kinase activity', got '...'`.

## Why a pipeline?

CARD/ARO has **no native ARO→GO mapping** (verified against `aro.owl`). We supply the
ARO→GO bridge as curated SSSOM, then need a **UniProt→ARO** step to apply it to real
protein entries. There are two routes:

1. **`DR CARD` cross-reference (deterministic, sparse).** UniProt flat-files sometimes carry
   a CARD cross-reference, e.g.
   `DR   CARD; ARO:3000318; mphB; ARO:0001004; antibiotic inactivation.`
   This single line gives **both** the determinant ARO id *and* the resistance-mechanism ARO
   id for free. But UniProt only populates it for a minority of entries — in this repo,
   **1 of 2334** cached UniProt records (MphB). MphA (Q47396) has none. (The 4,182-entry snapshot in `data/` comes from the UniProt REST API, not from these cached records.)

2. **Sequence-based assignment with RGI (scalable).** CARD's
   [Resistance Gene Identifier](https://github.com/arpcard/rgi) assigns ARO ids to protein
   sequences. This is the route for entries lacking a `DR CARD` line. We do **not** run RGI
   in this script (it needs RGI + the local CARD database installed); instead we parse its
   output if you run it. Related: [`argNorm`](https://github.com/BigDataBiology/argNorm)
   normalises the output of RGI/AMRFinderPlus/ABRicate/etc. to ARO accessions.

## Propagation: which ARO relations are followed

ARO joins the two kinds of term that rows are written on by different relations:

- **Gene families** (e.g. `ARO:3000001` beta-lactamase): a GO term mapped at a family applies to a
  gene whose ARO assignment is that term or any `is_a` descendant (`exact` / `narrower`). This is why
  family-level nodes are the high-value targets: the single beta-lactamase row reaches thousands of
  allele terms.
- **Resistance mechanisms** (e.g. `ARO:0001004` antibiotic inactivation) are not `is_a` ancestors of
  any gene. ARO asserts `participates_in` (RO:0000056) from a family to a mechanism, e.g.
  `ARO:3000333` MPH participates_in `ARO:3000105` phosphorylation of antibiotic conferring
  resistance, which is_a antibiotic inactivation. A mechanism row therefore applies along
  `is_a* ∘ participates_in ∘ is_a*` (`participates_in`). The CARD team pointed out that the earlier
  is_a-only code made every mechanism row reach nothing.
- Not followed: `confers_resistance_to_antibiotic` / `confers_resistance_to_drug_class` (they point
  to the drug, a chemical), `part_of` / `has_part` (complex subunits, gene clusters) and the
  regulation relations.

The rule is implemented once, in `aro_release.applicable_subjects`, and used by both the pipeline and
the gain report. Demonstration:

```text
$ uv run python uniprot2aro2go.py --sssom aro2go.sssom.yaml --rgi-output examples/rgi_example_betalactamases.txt
gene_aro_id   gene_aro_label   mapped_aro_id   mapped_aro_label          aro_relation      go_id        go_label
ARO:3001878   CTX-M-15         ARO:0001004     antibiotic inactivation   participates_in   GO:0046677   response to antibiotic
ARO:3001878   CTX-M-15         ARO:3000001     beta-lactamase            narrower          GO:0008800   beta-lactamase activity
...
```

## Usage

Run via the just recipe (validates the SSSOM first, then runs the chain on the AMR genes):

```bash
just aro2go-pipeline
```

Or directly:

```bash
# Route 1 — DR CARD line(s) from cached UniProt record(s):
uv run python projects/ANTIMICROBIAL_RESISTANCE/uniprot2aro2go.py \
    --sssom projects/ANTIMICROBIAL_RESISTANCE/aro2go.sssom.yaml \
    genes/ECO8N/mphB/mphB-uniprot.txt

# Sweep every cached UniProt record (recursive glob; quote it):
uv run python projects/ANTIMICROBIAL_RESISTANCE/uniprot2aro2go.py \
    --sssom projects/ANTIMICROBIAL_RESISTANCE/aro2go.sssom.yaml \
    'genes/**/*-uniprot.txt' -o /tmp/aro2go_all.tsv

# Route 2 — parse RGI output (for entries without a DR CARD line, e.g. MphA):
uv run python projects/ANTIMICROBIAL_RESISTANCE/uniprot2aro2go.py \
    --sssom projects/ANTIMICROBIAL_RESISTANCE/aro2go.sssom.yaml \
    --rgi-output projects/ANTIMICROBIAL_RESISTANCE/examples/rgi_example_mphA.txt
```

To generate real RGI output for the sequence-based route:

```bash
rgi load --card_json card.json            # one-time, from https://card.mcmaster.ca/download
rgi main --input_sequence protein.faa --input_type protein --output_file rgi_out
# then pass rgi_out.txt to --rgi-output
```

## Output

A TSV of **candidate** GO annotations with full provenance — `uniprot_acc`,
`gene_aro_id`/`gene_aro_label` (the gene's ARO assignment), `mapped_aro_id`/`mapped_aro_label`
(the ARO term the mapping is on), `aro_relation` (`exact`, `narrower` or `participates_in`),
`predicate_id`/`predicate_label`, `go_id`/`go_label`, `mapping_justification`, and `route`
(`DR_CARD` or `RGI`).

These are **leads for a curator, not final annotations**: the `enables`/`relatedMatch` predicates
indicate the relationship type, and a family-level mapping is only a prior for its members. As a
sanity check, the pipeline reproduces exactly the GO terms curators assigned by hand:

- **MphB** (`DR CARD` route) → `GO:0050073` macrolide 2'-kinase activity + `GO:0046677` response to antibiotic
- **MphA** (RGI route) → `GO:0050073` macrolide 2'-kinase activity + `GO:0046677` response to antibiotic
  (the BP now reaches MphA through MPH participates_in phosphorylation of antibiotic)

Both now come from the MPH family row (`narrower`), since the mphA/mphB determinant rows were removed.

## Coverage

See [FAMILY_COVERAGE.md](FAMILY_COVERAGE.md) for every CARD 4.0.2 AMR gene family (595). Rows are
grouped in `aro2go.sssom.yaml` as mechanism → BP, the CARD-reviewed family rows, the rows added after
that review (glycopeptide-resistance genes, site-specific rRNA methyltransferases, acquired
target-replacement enzymes, cell-envelope enzymes, ABC-F ribosomal protection, SMR pumps, porins), and
gap rows. Each row has a `confidence` and a justification in `comment`; rows the CARD team reviewed
carry `reviewer_label`. The mphA/mphB determinant rows were removed as redundant with the MPH family
row.

Unmapped families are listed in `aro_family_triage.yaml` with one of: `CHROMOSOMAL_VARIANT` (140;
resistance alleles of housekeeping genes, whose GO function is the wild-type gene's own),
`REGULATOR` (24), `NOT_IN_ONTOLOGY_RELEASE` (18; in CARD's category file but not in `aro.obo`),
`RRNA_VARIANT` (14), `DEFERRED` (14; plausible, not yet checked), `HETEROGENEOUS` (9; e.g. the ABC,
MFS, RND and MATE pump nodes, which mix complexes with single transporters), `NO_INFORMATIVE_MF` (6;
protection by binding), `UNKNOWN_FUNCTION` (3) and `GENE_CLUSTER` (2).

### Gaps: ARO families with no suitable GO term

Recorded in `aro2go.sssom.yaml` with `object_id: sssom:NoTermFound`. Eight have drafted GO new-term
requests ([GO_TERM_REQUESTS.md](GO_TERM_REQUESTS.md)); the D-Ala-D-Lac ligase gap closed because GO
now has `GO:0160220` D-alanine-(R)-lactate ligase activity.

## Release sync

`just fetch-aro` downloads the latest CARD release into `.cache/aro/` (git-ignored);
`just fetch-aro --update-pin` also makes it the pinned release. `just check-aro-release` then reports
label drift, ids gone from the release, new untriaged families, and triaged families that became
mapped. See [MAPPING_HOME_OPTIONS.md](MAPPING_HOME_OPTIONS.md) for where this should run long term.

## Validation & tests

- `just validate-mappings` — structural (`linkml-validate`) **and** ontology-term
  (`linkml-term-validator`, checks every ARO/GO id resolves + label matches).
- `just check-aro-release` — mapping and triage against the pinned CARD release.
- `tests/test_aro2go_mapping.py` — SSSOM structure, terms-file sync, propagation on a miniature ARO,
  the release checks, triage validation, and (integration) term-validator and release check.
- Doctests: `uv run python -m doctest projects/ANTIMICROBIAL_RESISTANCE/{aro_release,uniprot2aro2go,annotation_gain_report,render_sssom_html}.py`.
