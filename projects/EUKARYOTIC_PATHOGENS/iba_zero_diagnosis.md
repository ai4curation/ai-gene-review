## Draft GO/PANTHER issue

**Title:** PAINT/IBA export coverage for VEuPathDB pathogen and vector reference proteomes

**Body:**

We are using GO IBA annotations to triage VEuPathDB eukaryotic pathogen and vector proteomes for GO review. Several well-studied VEuPathDB organisms have UniProtKB proteins with PANTHER family cross-references but no IBA rows in QuickGO:

- Plasmodium vivax Sal-1 (`PLAVS`, taxon `126793`)
- Plasmodium berghei ANKA (`PLABA`, taxon `5823`)
- Trypanosoma cruzi (`TRYCR`, taxon `5693`)
- Leishmania donovani (`LEIDO`, taxon `5661`)
- Aedes aegypti (`AEDAE`, taxon `7159`)
- Toxoplasma gondii ME49 (`TOXGM`, taxon `508771`)
- Nakaseomyces glabratus CBS 138 (`CANGA`, taxon `284593`)
- Cryptococcus neoformans H99 (`CRYN9`, taxon `235443`)

Against GO release 2026-08-05 and PANTHER 19.0, these exact taxa are absent from `go-reference-species.yaml`, the PANTHER supported-genomes API, the PANTHER 19.0 sequence-classification file set, and the PANTHER PAINT leaf GAF snapshot 2026-08-28. Querying the species-level taxon in QuickGO also returns zero IBA rows, so this does not look like a strain-only query mismatch.

Can GO/PANTHER either add PAINT reference-proteome and IBA export coverage for these VEuPathDB organisms, or document why these current pathogen/vector proteomes are intentionally out of scope? Candida/Nakaseomyces glabratus is a useful edge case: GO already publishes `CANGA-mod` and `CANGA-uniprot` GAF/GPAD/GPI files, but neither carries PAINT/IBA rows because the PAINT reference set includes `CANAL` rather than `CANGA`.
