# PANTHER node PTN009058710: which GO term is true of every donor?

**A shared, node-level audit for three human paralogs — AADACL2, AADACL3 and AADACL4.**
All three carry one `GO:0016787 hydrolase activity` IBA row (`GO_REF:0000033`) whose
`WITH/FROM` field is the **same 17 tokens** in all three GOA records. That equality is
**measured for all three genes, not assumed for any of them**, from two independent sources:
the committed `AADACL2-goa.tsv`, `AADACL3-goa.tsv` and `AADACL4-goa.tsv`, and a per-accession
fetch from QuickGO (Q6P093, Q5VUY0, Q5VUY2), cross-checked against each other. A gene covered by
neither source is a hard error, not a silent gap. The QuickGO path was added when AADACL3's
review was still an open PR and its folder was absent here; it is kept now that it has merged,
because two sources agreeing is worth more than one. Because it is one row transferred
from one node, "could that row have carried a more specific term?" has a single answer for all
three genes, and it is audited once here instead of three times. It lives in the AADACL2 folder
because AADACL2's `RESULTS.md` already tabulates the per-node term assignment for the family;
the AADACL4 and AADACL3 reviews cite this file.

Reproduce with
`uv run --no-project --with requests python audit_node_PTN009058710.py`.
The agreement this audit settled is then held in place by
`uv run --no-project --with pyyaml python check_paralog_agreement.py` in this folder, which
enforces the six-row invariant across the three genes and greps the reviews, the notes files and
this prose for claims the harmonisation made false; `--self-test` breaks each of its eleven guards
in a temporary copy of the tree and requires each to fire.
Every number below is fetched at run time from the UniProt and QuickGO REST APIs plus the
committed GOA TSVs. Machine-readable output is `node_PTN009058710.json`, and this file is prose
written from it; the donor table and the counts are cross-checked against that JSON
programmatically rather than transcribed by eye.

Run date: 2026-07-26.

## Why this audit exists

*Historical: this section records the state that motivated the audit, not the current state. All
three reviews now record the same treatment — see the last section.*

Three reviews of the same row had reached three different verdicts. AADACL2 (PR #2266) replaced it
with `GO:0017171 serine hydrolase activity`; AADACL4 (PR #2263) and AADACL3 (PR #2264) both
replaced it with `GO:0052689 carboxylic ester hydrolase activity`, but disagreed about why —
AADACL4 recorded a `TERM_SCOPING_PROBLEM`, while AADACL3 argued the generic term is the genuine
lowest common ancestor of its donors and is replaceable only as *redundant*. At most one framing
could be right, and the donor set decides which.

## Method

For each of the 17 `WITH/FROM` tokens: resolve to UniProtKB (never with `size=1` — an
ambiguous cross-reference is reported, not resolved away), then read the chemistry off two
sources that are independent of the protein's **name** —

* the donor's own UniProt EC numbers and `CATALYTIC ACTIVITY` reactions, and
* the donor's own curated GO molecular-function annotations, classified by **fetched** GO
  ancestry (is the term under `GO:0052689`, under `GO:0016810` C–N-bond hydrolase, under
  `GO:0016829` lyase?),

and read the nucleophile off the donor's own `ACT_SITE` features. The nucleophile is the site
UniProt itself describes as the nucleophile where one is so described, otherwise the
N-terminal-most site of a nucleophile–acid–base triad; the acid/base order is *checked*, and a
donor whose sites do not follow it would be reported undetermined rather than guessed. The
GDXG nucleophile-elbow pentapeptide (G-x-[ST]-x-G, centred on the nucleophile) is reported
alongside each call so a positionally-inferred nucleophile can be checked at the sequence level
rather than taken on trust.

Each candidate term is then tested against every donor:

| candidate | what it requires of a donor |
|---|---|
| `GO:0016787` hydrolase activity | hydrolyses some bond |
| `GO:0052689` carboxylic ester hydrolase activity | hydrolyses a **carboxylic ester** bond |
| `GO:0017171` serine hydrolase activity | is a hydrolase **and** its nucleophile is a serine |

## The counts

```
GO:0016787 hydrolase activity:                  TRUE 16, FALSE 0, UNDETERMINED 0
GO:0052689 carboxylic ester hydrolase activity: TRUE 14, FALSE 2, UNDETERMINED 0
GO:0017171 serine hydrolase activity:           TRUE 15, FALSE 1, UNDETERMINED 0
```

**No donor refutes `GO:0016787`, and every more specific candidate is refuted by at least one
donor.** The two refutations lie on *different axes*, which is why neither proposed
replacement can be rescued by picking the other:

* the **bond-type** axis is blocked by the two kynurenine formamidases, mouse Afmid
  (`MGI:MGI:2448704` → Q8K4H1) and yeast BNA7 (`SGD:S000002836` → Q04066). Both are EC 3.5.1.9
  and both carry `GO:0004061 arylformamidase activity`, which sits under
  `GO:0016810 hydrolase activity, acting on carbon-nitrogen (but not peptide) bonds` — a
  *sibling* of the ester branch, not a descendant of it. Afmid's is IMP and BNA7's is IDA, so
  this is experimentally grounded amide chemistry, not a naming artefact.
* the **mechanism** axis is blocked by soybean HIDH (`UniProtKB:Q5NUF3`), whose
  nucleophile-elbow residue is **Thr164**, not a serine. `GO:0017171`'s definition demands "a
  catalytic triad consisting of a serine nucleophile", so the term is false of HIDH.

Since `GO:0016788` (ester bonds) and `GO:0016810` (C–N bonds) are siblings whose only common
ancestor below `GO:0003824` is `GO:0016787`, **`GO:0016787` is not merely unrefuted, it is the
exact lowest common ancestor of this donor set.** PAINT's choice at this node is correct
curation, and there is no granularity or term-scoping defect to fix in it.

### On what the Thr164 call rests, and whether the verdict depends on it

This one residue is what refutes `GO:0017171`, so it is worth being explicit about its
provenance. UniProt annotates HIDH's `ACT_SITE 164` as **"Proton acceptor"** (`ECO:0000305`),
not as a nucleophile — unlike Afmid and BNA7, where UniProt does label the nucleophile
explicitly. So the call is a **fold-position** inference: 164 is the N-terminal-most member of a
checked nucleophile–acid–base triad (T164–D263–H295), i.e. the elbow apex.

The sequence corroborates the position independently of any label. Fifteen of the sixteen
donors read **G-x-S-x-G** at the elbow — `GDSAG` in twelve of them, `GQSAG` in ICME, `GHSAG` in
Afmid and `GHSVG` in BNA7 — while HIDH alone reads **`GETSG`**, G-x-**T**-x-G. The serine at
the elbow apex is substituted by a threonine; there is a serine one position downstream (S165),
but no curated Ser–Asp–His triad exists for HIDH, so `GO:0017171` cannot be asserted of it on
present evidence.

The verdict does not depend on the positional rule, and the script measures that rather than
asserting it:

```
GO:0017171 sensitivity to the positional nucleophile rule:
  only_the_refuting_donor_undetermined: TRUE 15, FALSE 0, UNDETERMINED 1, true_of_every_donor=False
  every_positionally_inferred_nucleophile_undetermined: TRUE 2, FALSE 0, UNDETERMINED 14, true_of_every_donor=False
```

Downgrade HIDH from FALSE to UNDETERMINED and the term is still not true of every donor.
Downgrade *every* positionally-inferred nucleophile and the term is supportable for only the
two donors UniProt labels explicitly. Under all three readings, `GO:0016787` remains the only
term true of the whole set.

### One premise that was wrong, and it mattered

Both earlier reviews leaned on HIDH being "not a hydrolase at all but a dehydratase", which
would have threatened even `GO:0016787`. It does not. HIDH is bifunctional and *both* halves
are experimental: `GO:0033987 2-hydroxyisoflavanone dehydratase activity` by **IDA** and
`GO:0106435 carboxylesterase activity` by **IDA**, alongside its two EC numbers 4.2.1.105 and
3.1.1.1. So HIDH is a genuine, if physiologically minor, carboxylic-ester hydrolase; it
refutes the *serine* term only. Correspondingly it does **not** block `GO:0052689` — the two
formamidases do.

A second correction: yeast BNA7 does resolve. Querying `xref:sgd-S000002836` returns Q04066
KFA_YEAST directly, with `ACT_SITE 110` described by UniProt as the nucleophile and read from
the sequence as **Ser**. The AADACL3 audit reached it through an Alliance record instead and
reported its nucleophile unresolved, which undercounted the serine tally. With BNA7 resolved
the tally is **15 of 16 donors with a serine nucleophile, one with a threonine** — and both
formamidases are themselves serine hydrolases, so amide chemistry is no obstacle to the
mechanism term. The two blockers really are one each, on two axes.

## Where the mechanism term does belong

`GO:0017171` is not wrong about this family — it is attached to the wrong node. The same GOA
records carry a second IBA row, `GO:0016020 membrane`, transferred from the **family** node
`PTN009058713`, and its `WITH/FROM` names only three donors: human AADAC, mouse Aadac and
mouse Nceh1. Restricting the audit to that donor set — which is **the set PAINT cites at that
node, not an enumeration of the node's membership**: the PANTHER tree is not fetched here, and
what a PAINT node annotation rests on is the experimental donors available to it —

* all three are `IPR017157` (Arylacetamide deacetylase) members — as is rat Aadac, the fourth
  and only other `IPR017157` member in the whole 17-token set;
* all three have a serine nucleophile and all three are carboxylic-ester hydrolases, so both
  `GO:0052689` and `GO:0017171` are TRUE of every one of them;
* **all three carry `GO:0017171` by IDA** — human AADAC (`IBA,IDA,IEA`), mouse Aadac
  (`IBA,IDA,IEA,ISO`) and mouse Nceh1 (`IBA,IDA`). Not two of three: every donor PAINT cites at
  the family node holds the mechanism term experimentally.

And all three blockers at the deep node lie **outside** `IPR017157`: HIDH matches only
`IPR013094` and `IPR029058`, Afmid only `IPR050300` and `IPR029058`, BNA7 only `IPR013094` and
`IPR029058`. That is the independently measured half of the argument: membership of
`PTN009058713` itself is not enumerated, but the members that force the deep node up to bare
`hydrolase activity` are demonstrably outside the family signature the node corresponds to, and
none of them appears among the donors PAINT cites there.

**The PAINT recommendation this supports is therefore a node move, not a term change on the
row: place `GO:0017171 serine hydrolase activity` at `PTN009058713`, where it is true of every
donor PAINT cites there and IDA-supported by all three of them, instead of only at the
ortholog-specific nodes
`PTN002745055` (AADAC) and `PTN002745068` (NCEH1). That one edit would give AADACL2, AADACL3
and AADACL4 a mechanism term they currently inherit from nothing.** It cannot be reached by
editing the `PTN009058710` row, because that node's donors do not support it.

## What this means for the three reviews

* The `GO:0016787` IBA row is **correct, correctly scoped, and validly transferred** in all
  three genes. It is not an over-annotation, not a granularity defect and not a term-scoping
  error. `GRANULARITY_MISMATCH` does not apply: the donors disagree, so the parent term is the
  LCA rather than a term sitting needlessly above agreeing donors.
* What is nevertheless true of the row is that it is **subsumed by a better-provenanced
  annotation each gene already carries**: `GO:0052689` from `InterPro:IPR017157`, the
  subfamily-specific Arylacetamide deacetylase signature, which each of AADACL2, AADACL3 and
  AADACL4 has as its own IEA row. That is redundancy, i.e.
  `root_cause: EVIDENCE_CIRCULAR_OR_REDUNDANT` — "the target already has stronger direct
  evidence" — and it is the only defensible ground for replacing the row.
* AADACL2's `GO:0017171` replacement asserted of the row something one of its own donors
  refutes and the transfer does not license. It also contradicted AADACL2's own `RESULTS.md`,
  which had already concluded that this node is "so broad that bare `hydrolase activity` is all
  it can safely carry".

**Settled outcome.** AADACL2, AADACL3 and AADACL4 now all record this row as `MODIFY` →
`GO:0052689` with `root_cause: EVIDENCE_CIRCULAR_OR_REDUNDANT` and no granularity failure mode,
and all three raise the mechanism term as a node move to `PTN009058713` rather than asserting it
on the row.
