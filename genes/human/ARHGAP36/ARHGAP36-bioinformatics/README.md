# ARHGAP36 bioinformatics

## Question

ARHGAP36 (Q6ZRI8) has **no experimental GO annotation at all**. Its molecular function
comes from one IBA, `GO:0005096 GTPase activator activity`, propagated from PAINT node
`PTN000973894` (seeded by mouse Arhgap6, MGI:1196332), and UniProt separately asserts the
same function in its FUNCTION comment on `ECO:0000250` — by similarity.

The same UniProt entry annotates an "Arginine finger" Site inside the Rho-GAP domain. A
RhoGAP catalyses by inserting that arginine into the GTPase active site, so the residue
there is the most direct sequence-level statement available about whether this protein can
do the job.

This directory measures that residue, and then tries to break its own answer.

## Run

```
uv run --no-project --with "biopython>=1.85" python analyze_arhgap36.py
uv run --no-project --with "biopython>=1.85" python analyze_arhgap36.py --self-test
```

Everything is fetched live from UniProt, RCSB and the PROSITE cross-reference index and
cached under `cache/` (git-ignored). There is no offline fallback and no hardcoded result:
a missing input is a hard error naming the fix, never a silently dropped section.
`RESULTS.md` and `results.json` are regenerated by a run — do not hand-edit them.

## Files

| file | what it is |
|---|---|
| `analyze_arhgap36.py` | the analysis, plus `--self-test` |

## What it measures

1. **What UniProt says about itself** — the annotated arginine-finger position, the
   residue there, and the evidence codes on both the Site and the FUNCTION comment that
   asserts GAP activity.
2. **Whether that Site is in register.** A ProRule Site is placed by profile alignment and
   can be misplaced, so three controls carrying their own annotated arginine finger are
   projected onto ARHGAP36 domain-to-domain. Every control is also projected onto every
   other control: a method that cannot recover a *known* arginine finger has no standing
   to place ARHGAP36's.
3. **The escape test.** The one result that would rescue the annotation is an arginine
   displaced by a residue or two, so a ±10-residue window is scanned and the nearest
   arginine reported with its offset. This check is run and reported whatever it says.
4. **Agreement with the literature.** Three records name this residue in three different
   numberings — UniProt's canonical `258`, `Thr227` in PMID:33999959, and `T246` in
   PMID:25024229. Rather than assume which isoform each belongs to, the site is recomputed
   under the canonical sequence *and every upstream splice variant*, for the record of the
   species each paper worked in, and each published number is looked for among the results.
4c. **Whether the mouse ortholog shares the substitution.** This is the section that
   decides the node-placement argument: the IBD sits at a **Eumetazoa**-level node, so a
   substitution shared with mouse is one that predates almost everything the node
   propagates into. The ortholog's own Site is held to the same register test as the
   query's, and the two sites must project onto each other reciprocally.
5. **Whether the loss is ARHGAP36's or the family's** — scored for the PAINT seed, the
   human paralog in the same PANTHER family, and all 66 reviewed human PROSITE-RhoGAP
   proteins.
6. **Catalysis versus binding.** The GAP:GTPase interface from PDB 1TX4
   (p50RhoGAP:RhoA:GDP:AlF4, a transition-state mimic) is projected onto ARHGAP36 and, for
   scale, onto the PAINT seed.

## What this analysis does not claim

**A missing arginine finger is not by itself proof that a RhoGAP is dead.** The sibling
review of ARHGAP11B (`../../ARHGAP11B/ARHGAP11B-bioinformatics/`) measured the converse:
ARHGAP11B *retains* its arginine finger and is experimentally GAP-dead by two independent
IDA annotations. Residue identity and curated activity are decoupled in **both** directions
in this family. Section 5 re-derives the discrimination rate here so the weight of the
residue evidence is a number in this report rather than a claim borrowed from elsewhere,
and the inference is stated in one direction only.

The conclusion in the review does not rest on this analysis alone. The independent
functional evidence is that a systematic RhoGEF/RhoGAP screen found ARHGAP36 had no effect
on RAC1, CDC42 or RHOA (PMID:32203420, as reported in PMID:33999959), and Amin et al.
(PMID:27481945) place ARHGAP36 in their list of RHOGAP-domain proteins that lack the
arginine finger. This directory's job is to make the structural half of that argument
checkable rather than quoted.

## Guards, and the two bugs they caught

- **PDB numbering is not UniProt numbering.** The first run aborted: the contact
  calculation "did not recover `RHG01_HUMAN`'s own annotated arginine finger (282) among
  its 25 contacts". 1TX4 numbers its chain by the construct, offset ~197 from UniProt, so
  every contact had been placed in the wrong part of the protein. The fix maps structure
  numbering onto the UniProt sequence by alignment; the guard that caught it is the
  requirement that the calculation recover the control's own annotated finger.
- **A variant chosen by heuristic is a guess that can masquerade as a refutation.** The
  isoform cross-check first picked "the upstream variant that removes the most residues",
  which selected isoform 3 (`VSP_021357`, −136) and reported position 122 — i.e. that the
  sequence record *disagreed* with the published `Thr227`. The real answer is isoform 2
  (`VSP_021358`, −31 → 227). It now enumerates all upstream variants and reports which
  reproduces the published number, so no pick can be wrong. Enumerating rather than
  picking is also what surfaced the second published numbering: `T246` from PMID:25024229
  was already sitting in the human table under isoform 4, and turns out to be the mouse
  canonical position, which is how the ortholog check got written at all.
- **Prose that states a conclusion the run did not reach.** The same section printed
  "Two records reached this residue independently" unconditionally, including in the run
  where the match had failed. The sentence is now generated from the match result.
- **The `inactive` substring trap**, inherited from the sibling analysis and
  regression-tested here with the exact sentence that caused it: ARHGAP36's own FUNCTION
  line contains *"converting them to an inactive GDP-bound state"*, which describes the
  GTPase's nucleotide state and not the protein's catalytic status. The reader anchors on
  `GTPase activator` / `GTPase-activating` / `GAP for`, never on `active`.

`--self-test` asserts 16 propositions. Four are mutations that must flip a verdict
(restoring the arginine at the annotated site; the escape scan then reporting offset 0; an
unreachable published position; the *right* position with the wrong residue — the failure
a position-only check would miss). Two are negative controls that must stay silent: a
substitution 60 residues away must change neither the residue verdict nor the escape scan.
Four are guards that must raise. The rest are baselines, including the reciprocal
human↔mouse projection that the node-placement argument depends on. Every mutation asserts
its anchor holds the expected residue before mutating, so a drifted target is an error
rather than a vacuous pass. A passing self-test only proves the guards that were written
fire; it says nothing about the guard that was not.
