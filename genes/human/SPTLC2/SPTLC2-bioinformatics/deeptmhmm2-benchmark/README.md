# DeepTMHMM2 CPU benchmark

Small empirical runtime and memory benchmark using human SPTLC2 (O15270,
562 residues) and human DPM1 (O60762, 260 residues). This is a runtime probe,
not an independent evaluation of predictive accuracy or a gene review revision.

The [expanded 31-protein panel](panel-2026-11-05/README.md) reruns all 23 audited
S20 cases and adds eight controls, including long proteins, a multi-pass channel,
a beta barrel, and soluble secretory-pathway proteins. Its results and timings
are separate from this original two-protein pilot.

Run from this directory on macOS:

```sh
just install
just weights
just prepare
just benchmark
just marginals
just cli
```

`just weights` is a one-time setup in a fresh directory. ESM-2 weights are
downloaded automatically to the user's PyTorch cache on the first prediction.
The ten task-specific checkpoints are copied from the pinned source commit.
The isolated `pyproject.toml` and `uv.lock` preserve package versions. No
model files or virtual environments are version-controlled. `/usr/bin/time -l`
is macOS-specific; use `/usr/bin/time -v` on Linux.

`prepare_fasta.py OUTPUT INPUT...` accepts arbitrary UniProt flat-file paths.
`benchmark.py FASTA OUTPUT --model-dir DIRECTORY` accepts arbitrary input and
output paths. The benchmark uses the full five-model ensemble, CPU inference,
eight threads, and a fixed PyTorch seed. It measures import time, model load
time (including downloads on first use), individual prediction times, and
process peak RSS. Repeats reuse the loaded model but recompute embeddings.
The recipes use `--unbatch-api`, a local adapter for a bug in the pinned
upstream Python API: it passes a one-element list of topology strings into
postprocessing functions that expect a string. The adapter unwraps topology
and marginal outputs before postprocessing. It does not change model weights
or neural inference, and does not modify the installed package. Corrected
topologies and segments were checked against the unmodified CLI on both inputs.
Original buggy API outputs are retained under `results/api-unpatched-*` solely
for diagnostic provenance, not biological interpretation.

The API processes one protein at a time; these timings do not measure the
throughput of larger CLI batches. Export time is excluded from per-protein
inference timing but included in the process wall time. Marginals add posterior
probabilities; plotting is not part of these measurements.

Sources:

- [Prediction tool, pinned commit](https://github.com/fteufel/DeepTMHMM2/tree/526f6c60f93c0868c7315413da8e669d12373cc3)
- [Preprint](https://doi.org/10.64898/2026.08.24.746435)
- Canonical sequences extracted from the repository's cached UniProt files.

See `RESULTS.md` for measured results and interpretation, and `results/` for
raw output. Peak RSS is cumulative within each process, not a per-protein
increment. This two-protein sample does not establish proteome-scale runtime.
# Repository artifacts

JSON predictions, input manifests, timings and analysis reports are committed.
Equivalent per-sequence API GFF3, three-line and membrane-label TSV exports are
kept locally and regenerated by the benchmark recipes. CLI three-line files are
retained for sequence-identity and API/CLI comparison checks. Model weights and
Python environments remain in ignored caches.
